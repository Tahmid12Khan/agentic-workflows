# adversarial-code-review

Advisory, criticality-aware code review plugin for Claude Code. Reads a diff, scales review depth to risk, adversarially verifies the unsure findings, and reports them. **It never edits the code under review.**

## Golden rules

1. **Advisory, never edits source — except one sanctioned opt-in exception.** No `lib/` module may author or persist a change to a reviewed file. The only writes allowed are review artifacts under `.adversarial-code-review/` (reports via `report.mjs`, the learnings store via `memory.mjs`; a WS9 one-release fallback shim still reads the old `.adverserial-code-review/` dir if only it exists). `checkout.mjs` may move git HEAD — it detaches onto the remote's latest pushed head for the review and **restores the original ref afterward**, refusing (never stashing) when the working tree is dirty — but it never commits or edits content. Findings carry a `fix` suggestion — rendered as text, never applied, by the review pipeline itself. The **only** write path to reviewed files is the explicit, confirmation-gated `/review-respond --fix` (`lib/respond.mjs` `applyFix`) — an author-side, opt-in exception, never invoked by `/review`. This invariant is stamped into user-facing output (`render.mjs` HTML footer, `comments.mjs` PR-comment footer); keep it true. **Every agent carries `Bash`** (so a reviewer can pull its own context instead of the pipeline pre-computing one), and what holds the invariant is `lib/allow-bash.mjs`, the `PreToolUse` guard wired by `hooks/hooks.json`: for a caller on this plugin's roster it is **deny-by-default** — only read-only commands pass, and redirection, command/process substitution, `sed -i`/`sed 'w file'`, `find -exec`/`-delete`, `-f` script files and `git -c` are refused. For any other caller it emits **no decision**, so a plugin hook never wedges the user's own shell. If you add a tool or loosen the allowlist, the burden is showing golden rule 1 still holds.
2. **Zero runtime dependencies.** Import `node:` builtins only. No npm packages, no flag-parsing libs, no test frameworks. `package.json` has no `dependencies`.
3. **Degrade to a skip note — never crash mid-run.** Probe for optional tools (`have('npm')`, `has('gh')`) up front; when something is missing or fails, push a human-readable string onto a `notes`/`skipped`/`warn` collection and keep going. Hard failure (`process.exit(1)`) is reserved for genuinely required tools (git), via `preflight.mjs`.
4. **Determinism.** No `Date`/random in any function that generates an identity (e.g. `findingKey`). Stable sorts use an explicit tie-break key.

## Module convention (`lib/*.mjs`)

Every module is one pipeline step, named for its verb (`scan`, `gather`, `triage`, `verify`, `render`, …). Shape:

- **Runnable modules**: `#!/usr/bin/env node` shebang → header comment block (`CLI:` purpose, `Usage:` line, what it reads/prints) → **pure exported functions first** → thin `main` last, guarded by `if (import.meta.url === \`file://${process.argv[1]}\`)`.
- `main` parses argv with a tiny local `arg(name, def)` helper (no flag library) or reads JSON from stdin, calls the pure functions, and writes one pretty-printed JSON object: `process.stdout.write(JSON.stringify(out, null, 2) + '\n')`.
- **Pure-only modules** (`signals.mjs`, `shard.mjs`, `triage.mjs`): no shebang, no `main` — just exported pure functions, with a leading `// Pure:` comment.
- Export every non-trivial helper so it is unit-testable. Naming: `lowerCamelCase` verb-first functions, `SCREAMING_SNAKE_CASE` constants/tables, `<verb>Args` for functions that build CLI/git argv arrays.
- Config is read optionally from `.adversarial-code-review/config.json` (a WS9 one-release fallback shim still reads the old `.adverserial-code-review/config.json` if only it exists) inside a try/catch defaulting to `{}`; every key has an inline `?? default`.
- Exit codes: `2` = usage/argument error, `1` = hard failure / gate BLOCK, `0` = success.
- Comments explain the **why** (the policy, the cost-of-miss tradeoff), not the mechanics.
- **Workflow-DSL exception**: `lib/review-workflow.mjs` is NOT a pipeline-step module — it has no shebang/`main` and uses the harness Workflow globals (`agent`/`pipeline`/`phase`/`args`). It cannot be `import`ed or run with `node`; it inlines the pure helpers whose canonical, tested copies live in `lib/review-orchestration.mjs` (orchestration helpers, plus `parseWorkflowArgs` — the sandbox's entry point, since the harness hands `args` over as a **JSON string** the orchestrator emits verbatim; it parses it and recovers from surplus trailing braces, which is transcription drift over the nested tail, while still refusing a truncated or mid-corrupted payload), `lib/verify.mjs` (the verification policy — `selectForVerification`/`resolveVerification`/`partition` plus the batched-verify grouping helpers `groupForVerification`/`distributeSeats`/`binByFile` and the risk-path check `isOnRiskPath`; the legacy per-finding cheap→strong escalation decision `firstPassModel`/`shouldEscalate` is deliberately NOT inlined — the workflow does escalation with a simpler group-level severity check instead, kept only for the legacy per-finding path + config back-compat; `verifyPolicy`/`cleanVerify` are also deliberately NOT inlined — config is resolved once in `plan.mjs` and the sandbox consumes the resolved camelCase `plan.verify` as-is), and `lib/trim-diff.mjs` (`normPath`, the finding-path normalizer that `inDiffScope` keys on, plus `sliceName`, the derived per-file slice filename both sides must agree on). A parametrized body-equality sync test (`tests/review-orchestration.test.mjs`'s `SYNCED_FUNCTIONS` table) extracts each inlined function's full source from both the canonical file and `review-workflow.mjs` and asserts normalized-whitespace textual equality, so a drift in an inlined copy fails CI rather than silently diverging — keep the inlined copies in sync with their canonical sources. **Caveat when adding to that table**: the extractor counts braces naively, with no awareness of strings, regexes or comments, so a literal `\x7d` anywhere in the body ends extraction early and the test then compares only the prefix — passing while blind to drift past that point. Write the body without a literal closing brace (see `parseWorkflowArgs`, which uses `\x7d` in its regex on purpose) and keep any constants it needs *inside* the function so it extracts as one self-contained unit (the `routedFiles` precedent). **Args-by-reference**: the diff is NOT inlined into the sandbox — `build-args.mjs` passes `args.diffPath` (+ `args.contextPackPath`, `args.historyPath`) and the reviewer/verifier agents `Read` the diff file themselves, focusing on their file list. So the sandbox no longer inlines `filterDiff`/`stripNoise`/`sectionPath`/`buildDiffIndex`; the only diff-derived datum it consumes, the off-diff line ranges, arrives as `args.diffRanges` — precomputed by `build-args.mjs` via `trim-diff.mjs`'s `buildDiffIndex` and **keyed by `sliceName(path)` rather than by path**. Likewise the per-file diff slices are addressed by `args.sliceDir` + a derived `sliceName`, not a path→path map. `args.diffIndex` survives as a legacy path-keyed escape hatch, non-null only when two reviewed paths collide on one slice name (build-args then disables slicing for the run).

**The reviewed file list is by reference too, and the sandbox never sees it.** `build-args.mjs` writes a per-shard manifest (`<scratch>/manifests/<n>-<label>.files`, `<path>\t<slice>` per line, plus `all.files` → `args.allManifest`) and `args.shards` carries `{label, count, manifest}`. `plan.files` is **deliberately not rebuilt** in the sandbox: every consumer of the list is an agent that `Read`s its manifest, and the off-diff demotion re-derives each finding's slice key from the finding's own path (equivalent, because `inDiffScope` only looks up files it has findings for). Leaving it undefined also keeps it out of the returned payload the orchestrator transcribes for `report.mjs` — nothing downstream reads it. Both shapes are supported: a shard with inline `files` and no `manifest` behaves exactly as before, which is the fallback when the manifest write fails and the shape `route.mjs`'s small scrutiny targets still use. When you add anything per-file to `args`, put it on disk instead — this payload must be emitted verbatim by a model, and length is what breaks it.

## Where things live

- **Review dimensions** (`Dn` ids) are defined in `lib/triage.mjs` — `DIMENSION_AGENTS`, `DIMENSION_LABELS`, `TIER_DIMENSIONS`, `OPUS_DIMS`, and the content gates in `planReview()`. Not in `config.schema.json` (it has no dimension enum) and not in `render.mjs` (it imports the maps). To add one, use `/add-reviewer-dimension`.
- **The intent-analyzer output is projected per consumer**, in `lib/review-orchestration.mjs` — never pass the raw object to an agent. `intentBrief` → the reviewer brief (scrutinize-group files as basenames), narrowed again per agent by `briefFor`/`CRITERIA_AGENTS` (only `correctness-reviewer` and `test-adequacy-reviewer` act on criteria; the rest get the summary alone — and their agent files must not claim otherwise, which a test enforces); `synthIntent` → the synthesizer; `criticIntent` → the exhaustive completeness-critic. The one exception is `screenPacket`, which keeps the **raw** intent on purpose: the cheap screen has no diff and no file list, so `harvester.groups[].files` is its only source of re-dispatch targets.
- **Bundled agents** live in `agents/`. The dimension reviewers (`*-reviewer.md`) share one finding contract; the pipeline agents (`intent-*`, `triage-classifier`, `*-verifier`, `completeness-critic`, `review-synthesizer`) each use their own JSON shape by design.
- **Severity vocabulary is fixed**: `critical | important | minor | suggestion` (lowercase). Never introduce `high`/`med`/`low`/`info`. The full finding contract is enforced by the `dimension-agent-consistency` agent — run it if you touch a reviewer's output.
- **Review orchestration** is a Workflow (`lib/review-workflow.mjs`), invoked by `commands/review.md`. The main agent only runs the deterministic scripts + the Workflow call; it never assembles the `report.mjs` payload by hand.

## Testing

`npm test` → `node --test` (built-in runner, no framework). Test files: `tests/<topic>.test.mjs`, importing `node:test` + `node:assert/strict`. Two layers: unit tests on the pure exports, and CLI smoke tests (`tests/cli.test.mjs`) that spawn each script via `process.execPath` and assert on the parsed JSON stdout. No network, no deps. Fixtures: JSON change-objects under `fixtures/cases/`.

## Versioning

The version is duplicated across the plugin manifests and they must agree (the `check-versions` hook flags drift). Source of truth: `.claude-plugin/plugin.json`. Use `/release-plugin` to bump them together and cut a release.

## Keep the docs current

`README.md` and `docs/ARCHITECTURE.md` are the user-facing contract. **When you change behavior, update them in the same change** — run `/sync-docs`, which maps each kind of code change to the doc sections it affects.

## Project skills

- `/add-reviewer-dimension` — scaffold a new dimension end to end (agent file + `triage.mjs` wiring + docs).
- `/release-plugin` — bump the version across every manifest, update `RELEASES.md` (+ `ROADMAP.md`), test, commit, tag.
- `/sync-docs` — reconcile `README.md` + `docs/ARCHITECTURE.md` with the current code.
