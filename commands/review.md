Flags: --pr <n> --base <ref> --comment --gate --tier <t> --max-tier <t> --effort <low|medium|high|max> --dimensions <list> --incremental --incremental-from <sha> --full --exhaustive --run-tests --no-checkout.

Run a systematic, **advisory** code review of the current change. NEVER modify source code — report only. You are a thin dispatcher: run the deterministic scripts, hand the fan-out to the Workflow, relay the result. Do not assemble report payloads by hand.

Bundled scripts live under `${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/adversarial-code-review}/lib/`. Let `LIB` be that path (resolve it to an absolute path). Run scripts with bare `node` — `preflight.mjs` validates node ≥ 18 and errors clearly if the resolved node is too old. (Do NOT use `command node`: on machines with a stale old node on PATH it bypasses the nvm lazy-loader and resolves the wrong version.)

## 1. Preflight
Capture the start time: `STARTED=$(date -u +%Y-%m-%dT%H:%M:%SZ)`.
Run `node "$LIB/preflight.mjs"`. If it exits non-zero, show the report and STOP.

## 2. Checkout (review the latest pushed code, at the GitHub-exact boundary)
Resolve base/head, fetch them, and **detach HEAD onto the latest pushed head** via `checkout.mjs` — so the reviewers' own `Read`/`Grep` see the real target code, not a stale local checkout. Read the `checkout` config block (defaults `enabled:true`, `remote:"origin"`, `fork_point:true`). Resolve head/base in this order:
- **`--pr <n>`** (review a specific PR — the loop/CI entrypoint): `gh pr view <n> --json number,baseRefName,headRefName` gives base/head/number. If `gh` is absent or the call fails, report it and STOP (you were asked for a specific PR).
- else **`--base <ref>`** wins for the base (head = current branch);
- else the **current branch's** PR (`gh pr view --json number,baseRefName,headRefName`);
- else default branch (base) vs current branch (head).

Skip the checkout — review the **working tree in place** — when `enabled:false`, `--no-checkout`, or reviewing uncommitted local changes (set `ORIGINAL_REF` empty, `checkout=null`). Otherwise `node "$LIB/checkout.mjs" setup --base <base> --head <head> --remote <remote> [--pr <n>]`.

- **On non-zero exit, show its stderr and STOP.** The common case is a dirty working tree git would overwrite — `checkout.mjs` prints a stash-and-rerun instruction; relay it verbatim. It **never stashes for you** — the user must `git stash`/`git commit` themselves and re-run.
- On success, set `checkout = { baseRef, baseSha, headRef, sha, baseCommit, headCommit }` (for the report — `baseCommit`/`headCommit` carry each side's branch, sha, subject, date and an `origin` block when the reviewed ref diverged from `<remote>/<branch>`) and `ORIGINAL_REF = <originalRef>` (to restore in step 5). HEAD is now detached on the head; **steps 3+ run in the main repo** (no separate cwd).

**The reviewed diff base is the FORK POINT, not the base tip.** Set `DIFF_BASE = checkout.baseSha` (the `merge-base(base,head)` `checkout.mjs` computed) — feed **that** as `--base` to plan/gather/capture-diff in step 3, so the reviewed range is the GitHub three-dot `base...head`: byte- and sha-identical to the PR's Files-changed tab **even when the base branch has advanced past the fork point** (a two-dot `baseRef..HEAD` would drag in base's newer commits as phantom deletions). Fall back to `checkout.baseRef` when `baseSha` is null (unrelated/shallow histories — `checkout.mjs` notes it) **or** when the `checkout` config sets `fork_point:false` (opt back into the two-dot range). For the **`--no-checkout`** path (working tree already on the head, e.g. an isolated worktree), compute the same base with `DIFF_BASE=$(node "$LIB/checkout.mjs" forkpoint --base <baseRef> | node -e 'let s="";process.stdin.on("data",d=>s+=d).on("end",()=>process.stdout.write(JSON.parse(s).baseSha||""))')`; if empty (or `fork_point:false`), use `<baseRef>`.

**Stale-base check.** If setup reports `behindBase.count > 0`, the PR head is behind its base. The reviewed diff is already GitHub-exact (three-dot from the fork point — no phantom deletions), but the branch has **not integrated** base's newer commits, a real merge/semantic-conflict risk. List `behindBase.commits` (sha + subject) and recommend the user rebase or merge `<base>` into the branch; ask whether to proceed. Advisory — do **not** hard-block; if the user proceeds, continue and note it in the delivered summary.

## 3. Deterministic inputs
**Token discipline — redirect every blob to a file under `$SCRATCH`; never read plan/bundle/diff into context.** Let `SCRATCH` be your scratchpad dir. The diff, plan and bundle are large (often 40–60 KB combined); reading them into context to "inspect" or to hand-assemble args is the main cost sink — don't. Only the small dynamic enrichment (a fetched ticket, the live PR object) ever touches context.

- `node "$LIB/plan.mjs" --base <DIFF_BASE>` (pass through `--tier`/`--max-tier`/`--effort`/`--dimensions`/`--exhaustive`/`--incremental`/`--incremental-from`/`--full`; `--effort <low|medium|high|max>` scales report/verify thresholds for THIS run without changing the tier — the gate never loosens below conf 80; `<DIFF_BASE>` is the fork-point sha from step 2, so the plan's tier/signals are computed on the GitHub-exact diff) **`> "$SCRATCH/plan.json"`**. With `--incremental` the plan narrows the reviewed range to only the commits added since the last review (`prevHead..head`) — but only on a fast-forward; a rebase/force-push falls open to the full `base..head` (see `plan.incremental`). `--full` forces the complete review. To branch on the tier, read just one field: `TIER=$(node -e 'process.stdout.write(require("$SCRATCH/plan.json").tier)')` — do **not** read the whole file. If `TIER == trivial`: do one quick inline correctness/comment pass, build a minimal payload (still including `plan` + `agentRuns:{}`) and skip to step 5.
- `node "$LIB/gather.mjs" --base <DIFF_BASE>` **`> "$SCRATCH/bundle.json"`**. Fetch linked tickets via the ClickUp/Atlassian **MCP** (never API tokens); if a tracker is enabled but its MCP is absent, ask once to connect, else skip. Write any dynamic enrichment (live PR object, fetched ticket, `trackerUsage`) as a small **`$SCRATCH/enrich.json`** — `build-args.mjs` merges it onto the bundle, so you never reshape the big bundle yourself.
- `node "$LIB/capture-diff.mjs" --base <DIFF_BASE> > "$SCRATCH/diff.txt"` — capture the **raw** unified diff at the GitHub-exact fork-point range, never read into context. Run this EXACT command; do **not** substitute `git diff` and do **not** reformat/summarize the output — the downstream parsers (`buildDiffIndex`, `context-pack.mjs`) key on raw `diff --git`/`@@` markers, so a stat-header or indented-hunk rewrite silently empties the diff index (every finding demoted out-of-diff) and the context pack (reviewers then wander the repo).
- `node "$LIB/context-pack.mjs" --diff "$SCRATCH/diff.txt" --stats-out "$SCRATCH/context-stats.json" > "$SCRATCH/context.txt"` — build the **shared context pack** (enclosing definitions of changed code, import blocks, in-repo callers of changed exports) once, from `$SCRATCH/diff.txt` + the checked-out working tree. `build-args.mjs` attaches its **path** as `args.contextPackPath`; the Workflow tells every reviewer to `Read` it before its own Read/Grep. Advisory + degrade-only — on any error it writes an empty/short file and `build-args` passes `contextPackPath: null`, so reviewers fall back to Read/Grep. Never read `context.txt` into your own context. The pack's size + per-section counts also land in `$SCRATCH/context-stats.json`, which `build-args.mjs` folds into `args.contextPackStats` for the report's "Agents & coverage" section.
- `node "$LIB/history.mjs" --diff "$SCRATCH/diff.txt" > "$SCRATCH/history.json"` — the deterministic **bug-history prior** (S6.3): per changed file, the recent `fix`/`bug`/`revert`/`hotfix`/`regression` commit subjects (`git log --oneline`). `build-args.mjs` attaches it as `args.history`; the Workflow rides it on the intent-analyzer + correctness packets so a file with a history of fixes gets extra scrutiny. Zero model cost; degrades to `{}` on a new file / no history.
- **`--run-tests` only** (off by default; **executes repo code** — never on an untrusted PR): `node "$LIB/test-signal.mjs" --diff "$SCRATCH/diff.txt" > "$SCRATCH/test-signal.json"` — runs the configured `tests.command` (never guessed) after checkout with a timeout; the `--diff` pass enables the untrusted-config guard (if the reviewed range modifies `.adversarial-code-review/config.json`, the command is NOT executed and a note is emitted instead — a PR must not choose the shell command run on your machine), capturing pass/fail + failing test **names** (no logs). `build-args.mjs` attaches it as `args.testSignal`; it feeds the test-adequacy-reviewer (D5) packet and the report header. Skip this step entirely without `--run-tests`.
- If `learning.enabled`: when a PR number is resolved (from `--pr` or `gh pr view`) and `.adversarial-code-review/posted-comments.json` (or `feedback.store` if configured) has an entry for it — i.e. a prior `--comment` run posted inline comments on this same PR — harvest the human 👍/👎/replies first: `node "$LIB/feedback.mjs" harvest --pr <n> [--store <feedback.store>] > "$SCRATCH/feedback.json"`, then fold it into the store: `node "$LIB/memory.mjs" feedback <store> --pr <n> < "$SCRATCH/feedback.json"`. Degrade-only — `feedback.mjs` itself never fails on a missing/absent `gh` (it emits `results:[]` + a note), so skip this pair of commands entirely when there's no PR number or no prior state, and don't let any error here block the review. Then `node "$LIB/memory.mjs" load <store>` → carry as context.
- If `scan.deps`: `node "$LIB/scan.mjs"` → seed D15 findings + notes (fold into `enrich.json`).
- Routing (deterministic): `echo '<grouper-or-empty>' | node "$LIB/route.mjs" scrutiny > "$SCRATCH/scrutiny.json"` and `echo '{"mandatoryChecks":<plan.mandatoryChecks>}' | node "$LIB/route.mjs" checks > "$SCRATCH/checks.json"`.

## 4. Hand the fan-out to the Workflow
The Workflow owns intent, dimension review (`dimensions × shards`), batched verification of the unsure findings (grouped by lens+file into ≤N sonnet-first verifier groups + 1 opus reverify guard, N per tier), resolve, and synthesize. It assembles the report **payload** but no longer renders it (the sandbox can't write files; rendering moves to step 5).

**Assemble args deterministically — do not hand-build it.** Write the small `$SCRATCH/meta.json` `{ "flags": { "comment": <bool>, "gate": <bool>, "incremental": <bool>, "exhaustive": <bool>, "runTests": <bool> }, "startedAt": "<STARTED>", "prNumber": <n|null>, "checkout": <step-2 object|null> }`. `prNumber` = the `--pr <n>` value if passed (so it survives even the `--no-checkout` path), else `checkout.prNumber`, else the current-branch PR number from `gh`, else null. Then:

```
node "$LIB/build-args.mjs" --dir "$SCRATCH" > "$SCRATCH/args.json"
```

`build-args.mjs` reads plan/bundle/diff/context/routing/meta/enrich from `$SCRATCH` and emits args in the exact shape the workflow destructures (`{ plan, bundle, diffPath, contextPackPath, diffIndex, shards, routing, flags, startedAt, prNumber, checkout }`). **Args-by-reference:** the bulky diff and context pack are passed as absolute **paths** (`diffPath`/`contextPackPath`), never their text — the Workflow's reviewer/verifier agents `Read` the diff file themselves and focus on their file list, so `args.json` stays a few KB and the diff never enters your context OR the Workflow tool call. The one diff-derived datum the sandbox needs (`diffIndex`, the compact off-diff line ranges) is precomputed here. Then read `args.json` **once** and pass it as the `args` value:

```
Workflow({ scriptPath: "$LIB/review-workflow.mjs", args: <contents of args.json> })
```

- Do **not** reshape, subset, or rename any field, and do **not** read `review-workflow.mjs` to infer what it wants — `build-args.mjs` already produces the complete, correct contract.
- `args` is delivered to the script as a **JSON string** — that is expected; the Workflow parses it. Pass it as an object here regardless.
- It returns `{ payload, needsHuman, notes }`. Only if the Workflow tool itself errors that `scriptPath` is unresolvable, read the file and pass its contents via `script` instead — never open it otherwise.

## 5. Deliver
- `--comment` **runs BEFORE `report.mjs`** (order matters — see below): `echo '{"findings":[enriched],"head":"<head>","base":"<DIFF_BASE>","prNumber":<n>,"existingComments":[...],"postedCommentsPath":"<feedback.store or default>"}' | node "$LIB/comments.mjs"` to post inline PR comments (requires `gh`). It seeds 👍/👎 on each posted comment and records comment-id → finding-key state at `postedCommentsPath` (default `.adversarial-code-review/posted-comments.json`) for a later run's feedback harvest (step 3) — best-effort, never blocks the post.
  - **Re-review convergence (WS3):** `comments.mjs` reads `.adversarial-code-review/last-review.json` itself (no extra plumbing needed here) and classifies this run's findings against the PREVIOUS run's: a finding no longer reported gets a reply — "✅ Resolved in `<sha>`" **and** the GitHub thread resolved, but only when its old file:line region actually changed between the two reviewed heads (a real `git diff`); otherwise it's replied to as "no longer reproduced" and the thread is left open. A finding reported in BOTH runs is never re-posted (it shows up in the report's "Still open" section instead). From the second review of the same PR on, `rereview.nit_rounds` (config, default 1) demotes minor/suggestion findings to report-only, and `report.max_posted_nits` (default 5) caps how many nits get posted at all — both print a one-line note to stdout.
  - This step must run **before** `report.mjs` specifically because `report.mjs` overwrites `last-review.json` at the end of its own run — if `--comment` ran after, it would be diffing this run's findings against themselves.
- **Render the report** (also the destination for the trivial path of step 3): write the `payload` JSON to a temp file and run `report.mjs` from the **repo root**:
  `node "$LIB/report.mjs"${gate ? ' --gate' : ''} < <payload.json>`.
  Read the printed `→ <folderPath>` and `Verdict: <X>` lines from its stdout. `report.mjs` degrades soft failures (memory, file write) to stderr notes and only exits non-zero on a missing-plan/agentRuns contract violation or, with `--gate`, a BLOCK verdict.
- Relay `folderPath` + verdict + any `notes` (workflow notes + report.mjs stderr) to the user.
- **Restore HEAD**: if step 2 detached HEAD (`ORIGINAL_REF` set), run `node "$LIB/checkout.mjs" restore --ref "$ORIGINAL_REF"` to put the user back on their original branch. Do this **after** the report is written. If it reports `restored:false`, warn the user they are on a detached HEAD and tell them how to get back (`git checkout <ORIGINAL_REF>`).
- Incremental state: `report.mjs` writes `.adversarial-code-review/last-review.json` (script-written, sha-keyed on the reviewed base/head + this run's findings) — do NOT write it by hand. It is written on every review so a later `--incremental` run has a prior head to narrow from. WS3 additions ride the same file: a `round` counter and, per finding, `severity`/`line`/`commentId` (best-effort, resolved from `postedCommentsPath` — accurate as of this run since `--comment` just ran).
- Notify: if `needsHuman` is non-empty and `notify.ask_on_unresolved`, present those questions as a short numbered list; their answers are saved to `.adversarial-code-review/learnings.json`.
